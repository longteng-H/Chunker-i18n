# Chunker 汉化（i18n）改造说明

> 基于 Chunker 1.19.1 源码的中文本地化改造记录，支持中文/英文切换。
> 改造范围：Electron 桌面版 UI（`app/ui`）。Java CLI（`cli/`）未改动。

## 一、功能概览

- 界面全量汉化（约 450 条字符串：组件文案 + 世界设置数据）
- 页脚 **English | 简体中文** 一键切换，当前语言高亮
- 首次启动按系统语言自动选择（`zh*` → 中文，否则英文）
- 语言偏好存入 `localStorage`（键：`chunker.lang`），重启保留
- 后端推送的字符串（设置分类名、进度名、Java/基岩版格式名等）同步翻译
- CSS 字体链追加中文回退（Microsoft YaHei / PingFang SC），无需打包字体

## 二、新增文件

| 文件 | 作用 |
|---|---|
| `app/ui/src/i18n/index.js` | i18n 核心模块：`t()` 词条翻译、`tt()` 后端字符串翻译、`getLang()` / `setLang()` / `getLanguages()` / `onLangChange()`、localStorage 持久化、系统语言检测 |
| `app/ui/src/i18n/locales/en.json` | 英文词条（234 条，含 `backend.*` 后端映射） |
| `app/ui/src/i18n/locales/zh-CN.json` | 中文词条（234 条，与英文逐键对应） |
| `app/ui/src/components/screen/settings/tab/world_settings/settings.zh-CN.json` | 世界设置中文数据（约 210 条，与 `settings.json` 结构逐键对应） |
| `app/ui/src/components/screen/settings/tab/world_settings/index.js` | `getMergeSettings()`：按当前语言返回对应的世界设置数据文件 |
| `app/electron/src/version.json` | 版本信息（非 git 环境下 pre-build 钩子不会生成，但主进程静态导入，缺失会启动崩溃，故手动补建） |

## 四、开发思路

1. **轻量自研，不引入 react-i18next**
   项目为 class 组件架构、零 i18n 基础设施，自研约 60 行模块即可满足需求，避免重依赖。

2. **双层翻译设计（核心决策）**
   - `t("key")` —— UI 自有字符串，扁平 key 查表
   - `tt("原文")` —— 后端/数据来源字符串。分类名、进度名等来自 Java 后端 websocket，无法改成 key，只能按英文原文映射（词条键为 `backend.<原文>`），查不到回退原文显示

3. **数据文件按语言拆分**
   世界设置 210 条为纯数据，拆成 `settings.json` / `settings.zh-CN.json` 两份结构完全一致的文件，后端合并逻辑零改动。

4. **显示时翻译，而非存储时翻译**
   `ProgressTracker` 内部始终存英文原名，渲染时才 `tt()`。切换语言立即生效，无需重建任何会话状态。

5. **切换机制**
   `setLang()` 写 localStorage → 通知监听者 → App `forceUpdate()` 全树重渲染；PureComponent 子树通过额外 `lang` prop 感知变化。

6. **打包策略**
   不重新编译 Java 后端：从官方 `Chunker-1.19.1-windows-x86.zip` 提取 `resources/chunker-cli`（含内置 JRE，版本未改）放到 `cli/build/libs/packaged/`，electron-builder 会将其作为 extraResources 打入。

## 五、踩坑记录（已修复）

| 问题 | 根因 | 修复 |
|---|---|---|
| 分类标签未汉化 | `tt()` 查嵌套对象 `backend[text]`，词条实际是扁平键 `backend.World Settings` | 改为查 `"backend." + text` |
| 构建失败 Module not found | 8 个文件 i18n 相对导入少写一级 | 按目录深度修正为 `../../../../i18n` / `../../../../../i18n` |
| 切语言后部分文案不变 | `CUSTOM_DIMENSION_FIELDS` 为模块级常量，import 时求值一次 | 改为函数 `getCustomDimensionFields()` 每次调用生成 |
| PureComponent 不刷新 | `forceUpdate` 不穿透 `PureComponent` | 父级传 `lang={getLang()}` prop |
| 打包后启动崩溃风险 | 非 git 环境 `pre-build.js` 跳过写 `version.json`，但 `src/index.js` 静态导入它 | 手动创建 `src/version.json` |

## 六、后续开发注意事项

1. **新增界面文字必须走 `t()`**，且 `en.json` / `zh-CN.json` 同步添加。词条一致性校验：
   ```powershell
   # 在 app/ui 目录执行，输出两份词条数量与差异键
   node -e "const a=Object.keys(require('./src/i18n/locales/en.json')),b=Object.keys(require('./src/i18n/locales/zh-CN.json'));console.log(a.length,b.length,a.filter(k=>!b.includes(k)),b.filter(k=>!a.includes(k)))"
   ```
2. **后端新字符串**（新进度名、新警告、新错误）：在两份词条的 `backend.*` 添加映射；不加不会崩溃，只会显示英文原文。
3. **世界设置新增条目**：两个 settings JSON 必须同步添加，**分类名与 setting 标识符必须逐字一致**（它们是后端合并的 key）；只有 `display` / `description` / 选项 `name` 可翻译。
4. **数据值不可翻译**：`NORMAL` / `FLAT` / `CUSTOM` / `VOID`、难度数值、广播范围数值等是发给后端的值，只能改显示名。
5. **已知边界**：
   - 世界预览 Leaflet 图层控件的维度名在 `componentDidMount` 构建，切换语言后需重新进入预览页才刷新
   - `public/index.html` 的 noscript 提示为静态 HTML，未汉化
   - `cli/` Java 命令行未汉化，如需需改 Java 源码
6. **打包流程**：
   ```powershell
   # 1. 构建 UI
   cd app\ui;      npm install; npm run build
   # 2. 打包 Electron（产物在 app\electron\dist\）
   cd app\electron; npm install; npm run publish
   ```
   - `dist\Chunker-1.19.1-i18n.exe`：便携版（x64）
   - `dist\win-unpacked\`：免安装目录版
   - 不需要 `-i18n` 后缀：删除 package.json 中的 `artifactName` 行即可
   - 需要 32 位：`electron-builder --ia32`（官方原包为 x86）
   - **打包/覆盖前先关闭正在运行的 Chunker**，否则文件被占用

# Chunker Localization (i18n) Notes

> Documentation of the Chinese localization work based on Chunker 1.19.1 source code, with switchable Chinese/English UI.
> Scope: Electron desktop UI (`app/ui`). The Java CLI (`cli/`) is unchanged.

## 1. Features

- Fully localized UI (~450 strings: component texts + world settings data)
- **English | 简体中文** switcher in the footer, active language highlighted
- Auto-detection on first launch (`zh*` system language → Chinese, otherwise English)
- Language preference persisted in `localStorage` (key: `chunker.lang`)
- Backend-provided strings (settings category names, progress names, Java/Bedrock format labels, etc.) are translated as well
- CSS font stacks extended with Chinese fallbacks (Microsoft YaHei / PingFang SC), no bundled fonts required

## 2. Added Files

| File | Purpose |
|---|---|
| `app/ui/src/i18n/index.js` | Core i18n module: `t()` dictionary lookup, `tt()` backend-string lookup, `getLang()` / `setLang()` / `getLanguages()` / `onLangChange()`, localStorage persistence, system language detection |
| `app/ui/src/i18n/locales/en.json` | English strings (234 keys, incl. `backend.*` mappings) |
| `app/ui/src/i18n/locales/zh-CN.json` | Chinese strings (234 keys, 1:1 with English) |
| `app/ui/src/components/screen/settings/tab/world_settings/settings.zh-CN.json` | Chinese world settings data (~210 entries, structure identical to `settings.json`) |
| `app/ui/src/components/screen/settings/tab/world_settings/index.js` | `getMergeSettings()`: returns the settings data file matching the current language |
| `app/electron/src/version.json` | Version info (in non-git environments the pre-build hook skips generating it, but the main process statically imports it and would crash without it, so it was created manually) |

## 4. Design Decisions

1. **Lightweight custom i18n instead of react-i18next**
   The project uses class components and had zero i18n infrastructure; a ~60-line module covers all needs without heavy dependencies.

2. **Two-layer translation design (key decision)**
   - `t("key")` — UI-owned strings, flat key lookup
   - `tt("source text")` — backend/data-origin strings. Category names, progress names, etc. come from the Java backend over websocket and cannot be turned into keys, so they are mapped by their exact English source text (locale keys are `backend.<source>`), falling back to the input when no translation exists

3. **Per-language data files**
   The ~210 world settings entries are pure data, split into `settings.json` / `settings.zh-CN.json` with identical structure, leaving the backend merge logic untouched.

4. **Translate at display time, not storage time**
   `ProgressTracker` always stores the English name internally; `tt()` is applied only when rendering. Language switches take effect immediately without rebuilding any session state.

5. **Switch mechanism**
   `setLang()` writes localStorage → notifies listeners → App `forceUpdate()` re-renders the whole tree; PureComponent subtrees detect changes via an extra `lang` prop.

6. **Packaging strategy**
   The Java backend is not rebuilt: `resources/chunker-cli` (with bundled JRE, unmodified 1.19.1) is extracted from the official `Chunker-1.19.1-windows-x86.zip` into `cli/build/libs/packaged/`, where electron-builder picks it up as extraResources.

## 5. Pitfalls (fixed)

| Issue | Root cause | Fix |
|---|---|---|
| Category tabs not translated | `tt()` looked up the nested object `backend[text]`, but locale keys are flat: `backend.World Settings` | Look up `"backend." + text` instead |
| Build failure: Module not found | 8 files had an i18n relative import one level too short | Corrected to `../../../../i18n` / `../../../../../i18n` by depth |
| Some texts stale after switching | `CUSTOM_DIMENSION_FIELDS` was a module-level constant evaluated once at import | Converted to function `getCustomDimensionFields()` evaluated per call |
| PureComponent not re-rendering | `forceUpdate` does not bypass `PureComponent` checks | Parent passes `lang={getLang()}` prop |
| Potential crash after packaging | In non-git environments `pre-build.js` skips writing `version.json`, but `src/index.js` statically imports it | Created `src/version.json` manually |

## 6. Notes for Future Development

1. **All new UI texts must go through `t()`**, added to both `en.json` and `zh-CN.json`. Consistency check:
   ```powershell
   # Run in app/ui; prints both key counts and any diff
   node -e "const a=Object.keys(require('./src/i18n/locales/en.json')),b=Object.keys(require('./src/i18n/locales/zh-CN.json'));console.log(a.length,b.length,a.filter(k=>!b.includes(k)),b.filter(k=>!a.includes(k)))"
   ```
2. **New backend strings** (new progress names, warnings, errors): add `backend.*` mappings to both locale files; missing entries do not crash, they just display the English source.
3. **New world settings entries**: must be added to both settings JSON files; **category names and setting identifiers must match character-for-character** (they are the merge keys against backend data); only `display` / `description` / option `name` may be translated.
4. **Data values must not be translated**: `NORMAL` / `FLAT` / `CUSTOM` / `VOID`, difficulty numbers, broadcast-range values, etc. are values sent to the backend — only display names may change.
5. **Known limitations**:
   - Leaflet layer control dimension names are built in `componentDidMount`; re-enter the preview tab after switching languages to refresh them
   - The noscript message in `public/index.html` is static HTML and remains untranslated
   - The `cli/` Java command line is not localized; localizing it requires Java source changes
6. **Build & package**:
   ```powershell
   # 1. Build the UI
   cd app\ui;      npm install; npm run build
   # 2. Package Electron (output in app\electron\dist\)
   cd app\electron; npm install; npm run publish
   ```
   - `dist\Chunker-1.19.1-i18n.exe`: portable build (x64)
   - `dist\win-unpacked\`: unpacked, installation-free build
   - To drop the `-i18n` suffix: remove the `artifactName` line from package.json
   - For 32-bit: `electron-builder --ia32` (the official package is x86)
   - **Close any running Chunker instance before packaging/overwriting**, otherwise files are locked
